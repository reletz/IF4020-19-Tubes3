    Nadina.Manifest (Nadina v0.1.0)

    Copy Markdown View Source

    Release manifest (spek Tabel 2.3): pembentukan, serialisasi canonical, dan parse strict.

    Byte hasil serialize/1 adalah pesan M yang ditandatangani. Saat verifikasi, parse/1 menerima byte M apa adanya dari bundle, memeriksa ukuran, struktur, nilai field, lalu membandingkan M byte-for-byte dengan hasil serialisasi ulang. Semua kesalahan parse/1 berarti FORMAT_ERROR.

    Nilai algorithm yang bukan salah satu profil tetap lolos parse/1 asalkan berupa string ASCII yang bisa ditulis tanpa escape, karena spek memisahkannya sebagai UNSUPPORTED_ALGORITHM. Gunakan supported_algorithm?/1 untuk langkah itu.

    Parse strict byte manifest dari bundle. Urutan pemeriksaan: ukuran (sebelum parsing), JSON strict dan struktur, nilai field, lalu kesesuaian serialisasi canonical.

    serialize(m)

    Serialisasi canonical: urutan field tetap, tanpa white space, tanpa escape, tanpa baris baru di akhir. Hanya untuk manifest yang sudah lolos new/7 atau parse/1.
